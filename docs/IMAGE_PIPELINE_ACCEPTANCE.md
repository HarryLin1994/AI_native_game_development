# Image Pipeline Acceptance

This document defines the current work focus and the acceptance gates for the photo-to-card-art pipeline.

Current focus:

```text
Source Photo
  -> Photo Signal
  -> OCR Text Seed
  -> Visible Semantic Tags
  -> Character Spec / Prompt Profile
  -> Identity-preserving picture generation
  -> Effect Review
```

Out of scope for the current phase:

- Enemy data.
- Battle simulator tuning.
- XP, leveling, and progression.
- Deck balance.
- Final card UI animation.

比喻：現在先確認「拍照後能不能畫出一張像本人、又有照片語意的角色圖」。戰鬥系統像下游比賽規則，等角色生成品質成立後再接。

## Input Types

The pipeline must keep these inputs separate:

| Input | Meaning | Example | Used by image generation |
|---|---|---|---|
| Source Photo Identity Reference | The consenting subject's face and broad likeness cues | face shape, eyes, nose/mouth proportions, expression character | Yes |
| Photo Signal | Low-level visual signals extracted by local analysis | palette, brightness, contrast, saturation, line density, center focus | Yes |
| OCR Text Seed | Actual visible text or symbols, from manual input or OCR | jersey text, sign text, badge text | Yes, as motif only |
| Visible Semantic Tags | Visible scene/action/state clues | basketball court, athlete, arcade room, holding a controller, sweaty, tired-looking, post-game energy | Yes |
| User-Supplied Context | Explicit creative context from the user/photo subject | job, backstory, signature item, values | Yes |
| Capture Context | Coarse optional context | indoor court, night, rainy, beach | Yes |

Important rule:

```text
Visible Semantic Tags must feed the image-generation prompt.
```

If they only affect stats or skills, the card art will not express the game's core promise.

Target source:

```text
Visible Semantic Tags should be generated by a local VLM, then reviewed or corrected by the user.
```

Current validation rule before the VLM adapter exists:

```text
Use manual VLM calibration tags to define what a good VLM answer should look like.
```

For example, the user can enter:

```text
basketball court, athlete, post-game energy, sweaty, sportswear
```

The app should group those tags into prompt-facing categories such as scene, activity, state, object, clothing, lighting, composition, and visual signal. A local Vision model can later suggest these tags, but the acceptance target should first be calibrated with tags the user agrees are correct.

Manual calibration is not the final product interaction. It is only a temporary way to define the expected VLM output quality.

Current adapter under test:

```text
POST /api/vision-tags
  -> image 1: browser-created center subject crop
  -> image 2: full source photo
  -> Ollama `/api/chat`
  -> default model `gemma3:4b`
  -> default subject focus `center_primary_subject`
  -> JSON groups: personAppearance, scene, activity, object, state, clothing, lighting, composition, visualSignal
```

The browser exposes this through the `VLM 解析` button. If Ollama is not running or the model is missing, the app should show the error clearly and keep manual calibration available.

Multi-person acceptance rule:

- `personAppearance`, Target Subject clothing, and Target Subject state should describe only one centered / largest / clearest foreground subject from the center crop.
- Background people can still appear as broad world-context tags such as crowd, teammate, audience, background people, or group scene.
- Scene, activity, object, lighting, composition, and visual signals should still use the full photo when relevant.

## Acceptance Gates

An image-generation result is useful only if it passes all gates below.

### 1. Technical Output

Pass criteria:

- Returns a valid image to the browser.
- Not near-black.
- No timeout under the current local experiment timeout.
- Single output image is saved for review.

### 2. Likeness Preservation

Pass criteria:

- Face shape and jaw impression still feel like the same person.
- Eye/brow spacing, nose/mouth proportions, and expression character remain recognizable.
- Hair or outfit can change, but the person's core facial identity should not be replaced.

This is creative likeness preservation, not identity verification.

### 3. Photo Semantic Transfer

Pass criteria:

- Visible Semantic Tags appear in the character art when provided.
- Person appearance, scene, activity, state, object, clothing, and lighting tags are represented in the prompt profile before image generation starts.
- Example: a basketball photo should influence athletic energy, court-like environment, sport props, motion, sweat, or post-game mood.
- The generated picture should show why this specific photo produced this specific card.

### 4. Clean Art Layer

Pass criteria:

- One main character.
- No baked card frame.
- No ornate border.
- No stat panel.
- No unreadable text.
- No multi-panel collage.
- No duplicated faces or broken face artifacts.

Card frame, HP, ATK, DEF, COST, names, and skill text belong to the game UI layer, not the generated image.

### 5. Anatomy And Source Proportion

Pass criteria:

- Human or humanlike characters have plausible real-world limb structure.
- Visible hands have five fingers per hand.
- No extra arms, extra hands, extra fingers, fused fingers, broken wrists, impossible joints, or unclear limb bundles.
- Head size, shoulder width, neck length, arm length, hand scale, and broad body proportion should reference the Source Photo.
- Face proportion should reference the Source Photo: face length/width impression, eye spacing, brow-to-eye distance, nose/mouth placement, jaw/chin impression, and expression character.
- Strongly stylized versions may simplify proportions, but the result must still look intentionally designed and physically coherent.
- Animal or mascot transformations must also have coherent anatomy. A cat-main version should be a cat protagonist with transferred identity cues, not a human with cat accessories.

比喻：美術風格可以換衣服、換世界、換畫法，但骨架不能亂掉。這是模型輸出能不能進入遊戲的基本門檻。

### 6. Card-Art Potential

Pass criteria:

- Looks like a new battle-character portrait, not only a photo retouch.
- Has enough composition clarity to sit behind a future card UI.
- Style can be pushed toward mobile RPG / trading-card art without losing likeness.

### 7. Art Direction Fit

Pass criteria:

- The output matches one selected Character Form Branch from [ART_DIRECTION.md](./ART_DIRECTION.md).
- The output matches one selected art style target from [ART_DIRECTION.md](./ART_DIRECTION.md).
- The selected form branch and art style target are clear enough that future outputs can form a coherent visual family.
- Style comparison outputs are judged by hard gates first, then by taste.
